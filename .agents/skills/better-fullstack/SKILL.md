# Better Fullstack Project

This project was generated by Better Fullstack. Treat the generated structure as
the source of truth when adding stack features, fixing bugs, or extending apps.

**This project was built with:** typescript ecosystem · next · nestjs backend (node) · orpc API · prisma/postgres · better-auth · tailwind. The authoritative record of these choices is `bts.jsonc`.

## Project Rules

- Use `pnpm` for package-manager commands.
- Do not start a dev server unless the user explicitly asks.
- Prefer package-local scripts over broad workspace commands.
- Keep generated stack choices in `bts.jsonc` in sync with scaffold changes.
- For new Better Fullstack options, prefer the local Better Fullstack CLI or MCP
  update flow instead of hand-authoring unrelated starter code.

## Add a route or resource

This project exposes a **orpc** API. Routers live in `packages/api/src/routers/`, wired together in `packages/api/src/routers/index.ts`.

- Fastest path - scaffold a CRUD resource with the generator:

  ```bash
  pnpm dlx create-better-fullstack gen resource <name>
  ```

  It writes `packages/api/src/routers/<name>.ts` (auto-registered in `routers/index.ts`) using `protectedProcedure` (auth-gated) for every handler.

- Manual path - create `packages/api/src/routers/<name>.ts` exporting a `<name>Router`, then import it in `routers/index.ts` and add `<name>: <name>Router` to `appRouter`.
- oRPC procedures chain `.input(z.object({ ... }))` then `.handler(...)`; `appRouter` is a plain object literal of procedures.

## Run migrations

Schema lives in `packages/db/prisma/schema/`. After editing it:

```bash
pnpm run db:migrate    # prisma migrate dev (create + apply migration)
pnpm run db:generate   # prisma generate (regenerate the client)
```

For rapid local iteration you can push the schema directly with `pnpm run db:push` (prisma db push).

## Add a test

Unit tests use **Vitest**. Add `*.test.ts` files next to the code under test and run:

```bash
pnpm run test
```
